# 메타분석 가능성 예측기 (MA Feasibility Predictor) — 설계 스펙

- 작성일: 2026-10-15
- 대상 코드베이스: SR Studio V36.6
- 상태: 사용자 검토 대기

## 1. 목적과 성공 기준

**목적.** PICO, outcome, DB별 검색식을 입력하면, 전체 SR을 수행하기 *전에* outcome별로 메타분석에 쓸 수 있는 독립 연구 수(k)를 **구간으로** 예측한다. 이렇게 하면 SR을 끝까지 진행한 뒤에야 k가 부족하다는 것을 알게 되는 시간 손실을 막을 수 있다.

**정확도의 정의.** 이 도구가 내세우는 정확도는 점추정이 아니라 *구간의 보정(calibration)* 이다. 즉 "80% 구간이 실제 k를 약 80% 확률로 포함하는가"를 기준으로 삼는다. 이 정확도는 사용자가 완료한 과거 SR들을 이용해 **재연 검증(§7)으로 측정해 보고**하며, 측정 없이 주장하지 않는다.

**합격 기준 (leave-one-SR-out 재연 검증):**

| 지표 | 기준 |
|---|---|
| 80% 구간의 경험적 포함률 | 72–90% |
| 50% 구간의 경험적 포함률 | 40–62% |
| 진행/비진행 판정 정확도 (임계 k는 사용자가 설정, 기본값 5) | ≥ 85% (보류 판정은 별도 집계) |
| 중앙값 예측의 \|log(예측/실제)\| 중앙값 | 보고만 함 (게이트 아님) |

기준에 미달하면 UI에 "미검증 추정"이라고 표시하고, 미달한 지표를 그대로 보여준다.

**사용자 부담 목표.** 판정할 표본은 초록 단계 150–250편(정확한 기본값은 §7의 재연으로 결정)이고, 표본에서 통과한 문헌만 전문 확인을 한다. 비용은 0원이다.

## 2. 범위 밖 (Non-goals)

- 로그인·결제·다중 사용자·호스팅 같은 상용 운영 인프라. 정확도 게이트를 통과한 뒤의 별도 프로젝트로 둔다.
- 유료 DB API(Scopus, WoS, Embase)의 자동 실행. 사용자가 export 파일을 올리거나 hit 수를 입력하는 방식으로 대체한다.
- LLM을 최종 판정자로 쓰는 것. LLM은 제안만 하고, 확정은 사람이 한다.
- 유료 전문의 자동 다운로드.

## 3. 입력 / 출력

**입력**
- PICO/PECO 텍스트와 제외 기준
- outcome 목록. 각 outcome에 선택적으로 동의어를 줄 수 있다 (예: `TG: triglyceride, triacylglycerol, TAG`).
- DB별 검색식
  - PubMed, Europe PMC, OpenAlex: 자동 실행
  - 기타 DB: export 파일 업로드(RIS/NBIB/CIW/CSV/XLSX, 기존 `importers.py`) 또는 hit 수만 입력
- 진행 판단에 쓸 임계 k (기본값 5)

**출력**
- outcome별로 다음을 낸다.
  - 예측 k의 중앙값과 50/80/95% 구간
  - P(k ≥ 임계값)
  - 판정: 진행 / 보류 / 비진행
- 단계별 추정치: 고유 N, 초록 통과 수, 전문 포함 수, outcome별 정량 데이터 보유율. 각각에 구간을 붙인다.
- 보류 판정일 때는 구간을 좁히는 데 필요한 추가 표본 수와 그 표본을 뽑을 층을 권고한다.
- 감사용 XLSX를 내보낸다. 내용은 실행 메타데이터, 표본, 판정, 근거 문장, 사용한 사전분포, 검증 성적, 방법론 문단이다.

## 5. 데이터 흐름

1. **검색**: 각 DB 검색을 실행하고 건수와 레코드(제목, 초록, DOI, PMID, 연도)를 받는다. 응답은 질의 해시를 키로 디스크에 캐시해 재현할 수 있게 한다.
2. **모집단 N_U**: 레코드를 받은 DB들은 병합하고 중복을 제거해 고유 수를 구한다. 건수만 입력된 DB j는 기여분을 `count_j × (1 − overlap_j)`로 계산한다.
   - overlap_j의 사전분포는 라이브러리에서 관찰한 DB 간 중복률로 정하고, 관찰값이 없으면 Beta(2,2)를 쓴다.
   - 건수만 있는 DB의 레코드는 관련도 점수가 없다. 이 레코드들은 API로 받은 레코드와 **같은 층 분포를 가진다고 가정**한다. 이 가정은 UI에 명시하고, 재연에서 영향을 측정한다.
3. **층화**: PICO 관련도 점수(TF-IDF, 임베딩이 있으면 병용)로 정렬한다.
   - 상위 층은 전수 조사한다 (기존 STRATUM_ALLOCATION 방식).
   - 중·하위 층은 표본을 뽑는다. 층 수와 경계는 재연 검증으로 정한다.
4. **1차 표본 판정**: 사용자가 표본의 제목·초록을 보고 "전문 검토로 넘김(O) / 제외(X)"를 판정한다. 로컬 LLM이 있으면 판정 제안과 근거 문장을 미리 채워 둔다.
5. **2차 적응 표본**: 1차 결과로 층별 유병률을 추정하고, 사후분산을 가장 많이 줄이는 층에 추가 표본을 배분한다 (Neyman 배분, `√(p(1−p))·N_h`).
6. **전문 단계**: 표본에서 O로 판정된 문헌의 OA 전문을 자동으로 확보한다. 실패하면 사용자가 PDF를 올린다.
   - 규칙 탐지기와 LLM(선택)이 outcome별 정량 데이터 후보와 근거 문장을 제시한다.
   - 사용자는 문헌마다 "최종 포함 여부"와 "outcome별 정량 데이터 있음/없음"을 확정한다.
   - 전문을 끝내 확보하지 못한 문헌은 *결측*으로 남긴다. 제외로 처리하지 않는다.
7. **추정**: §6의 방법으로 계산한다.
8. **보고**: §3의 출력을 낸다.

## 6. 통계 모형

**단계 정의.** 모집단의 레코드 i마다 다음 지표를 둔다.
- Z1_i: 초록 단계를 통과해 전문 검토로 넘어감
- Z2_i: 전문 검토 후 최종 포함 (Z1_i = 1인 경우에만 정의)
- Z3_io: outcome o에 대해 효과크기를 계산할 정량 데이터가 있음 (Z2_i = 1인 경우에만 정의)

목표량은 outcome o의 k_o = Σ_i Z1·Z2·Z3_o 를 독립 연구 단위로 환산한 값이다.

**① 초록 통과 수 T1**
- 층 h마다 모집단 N_h, 표본 n_h, 통과 x_h를 둔다.
- 사후분포: p_h ~ Beta(x_h + a_h, n_h − x_h + b_h)
- 표본에 뽑히지 않은 나머지 레코드 중 통과 수는 BetaBinomial(N_h − n_h, ·)로 예측한다. 이렇게 하면 유한모집단 보정이 자동으로 들어간다.
- 전수 조사한 층은 불확실성이 0이다.
- (a_h, b_h)는 기본적으로 Jeffreys (0.5, 0.5)를 쓴다. 다만 하위 층은 포함 0편이 흔하다. 그래서 라이브러리에서 "같은 관련도 분위의 유병률" 분포를 적합한 약한 정보 사전분포를 쓴다 (priors.py).

**② 전문 포함률 q2 = P(Z2 | Z1)**
- 표본 내 Z1 문헌 중 전문을 확인한 m편, 그중 포함 y편으로 추정한다.
- 사전분포는 라이브러리 SR들의 q2로 적합한 계층 Beta이고, 집중도 κ는 leave-one-SR-out으로 적합한다.
- 전문 결측 문헌은 MAR(무작위 결측)을 기본 가정으로 둔다. 민감도 분석으로 "결측 전부 제외"와 "결측 전부 포함"의 두 극단 구간도 함께 보고한다.

**③ outcome별 정량 보유율 q3_o = P(Z3_o | Z2)**
- 전문으로 확인한 포함 문헌에서 계산한다.
- 사전분포는 outcome 일반 사전(라이브러리 전체)이다. 사용자가 outcome 유형(혈액지질 / 조직 중량 / 유전자 발현 / 기능검사 등)을 고르면 그 유형의 사전을 쓴다.

**④ 독립 연구 환산**
- 보고서와 연구의 비율 r은 라이브러리에서 관찰한 "포함 논문 수 대비 고유 Study 수"로 정하며, 사전분포로 쓴다.

**⑤ 합성**
- Monte Carlo로 S = 10,000회 반복한다. 매 반복마다 다음을 순서대로 뽑는다.
  1. 모든 사후분포에서 모수를 뽑는다.
  2. T1 ~ Σ_h (x_h + BetaBinom)
  3. T2 ~ Bin(T1, q2)
  4. K_o ~ Bin(T2, q3_o)
  5. 독립 연구 환산을 적용한다.
- 반복 결과의 분위수로 구간을 만든다.
- 여러 outcome은 같은 T2를 공유하므로 결합분포가 자연스럽게 유지된다.

**⑥ 판정 규칙**
- P(K_o ≥ 임계값) ≥ 0.8 이면 진행
- P(K_o ≥ 임계값) ≤ 0.2 이면 비진행
- 그 사이는 보류. 이때는 추가 표본 권고를 낸다.
- 0.8/0.2 경계값은 재연 검증으로 보정한다.

**⑦ 사전분포의 정보 누출 방지.** 재연 검증에서 대상 SR은 자기 자신을 사전분포 적합에 쓰지 않는다 (중첩 leave-one-SR-out).

**ETL 규칙 (library/manifest.py에 워크북별로 명시)**
- 라벨 매핑
  - `o/O/ㅇ` → 1, `x/X` → 0
  - `△`, `&`, `$`, `애매` → 0.5 (애매). 다음 단계로 넘긴 것으로 처리한다. SR 관행과 같다.
  - `위와 동일` → 직전 행의 값
  - `#REF!`, 빈칸 → 결측
- 판정 열 우선순위: 최종 판정 열(판정 / 최종선택 / 제3자)이 있으면 그것을 쓴다. 없으면 검토자 중 한 명이라도 O면 통과로 본다. 제목 단계의 관행이다.
- 단계 연결: 제목 → 초록 → 전문 시트를 정규화 제목으로 매칭한다. 정확히 일치하지 않으면 rapidfuzz ≥ 95로 매칭하고, 매칭률을 보고한다.
- 출력: `library/<id>/records.csv`, `outcomes.csv`, `meta.json` (PICO 텍스트, DB별 건수)
- 원자료는 사용자의 연구 데이터다. 그래서 `library/` 폴더는 .gitignore에 넣고 배포 ZIP에 포함하지 않는다. 배포에는 적합된 사전분포 계수(`priors.json`)만 포함한다.

**재연 절차 (replay.py)**
1. 대상 SR의 제목 단계 레코드 전체를 모집단으로 둔다.
2. 그 SR의 PICO 텍스트로 관련도 점수를 매긴다.
   - 대부분의 시트에 초록이 없어서 제목만으로 점수를 매긴다.
   - 실제 사용 시에는 초록이 있으므로, 이 조건은 실제보다 *불리한* 쪽이다.
3. 설계한 표본 추출을 수행하고, 정답 라벨(초록 단계 진입 여부)을 공개한다.
4. 표본 통과 문헌의 전문 단계 결과(포함/배제/전문 미확보)를 정답에서 공개한다.
   - outcome별 Z3는 포함 문헌 중 실제 k_o개를 무작위로 배정한다 (교환가능성 가정).
5. 다른 SR들로 적합한 사전분포로 k를 추정한다.
6. 1~5를 시드 1,000개로 반복해 포함률, 판정 정확도, 구간 폭, 사용자 판정 편수를 집계한다.
7. 표본 크기(100/150/200/250/300)와 층 설계 후보별로 1~6을 반복하고, 합격 기준을 만족하는 가장 작은 설계를 기본값으로 정한다.

**한계 (보고서에 명시)**
- 검증 단위가 8개 SR이고, 같은 SR 안의 outcome들은 서로 상관된다. 그래서 포함률 자체에 Wilson 구간을 붙이고 SR별 결과를 분해해서 보고한다.
- 재연은 사용자의 판정이 과거 SR의 판정과 같다고 가정한다. 즉 검토자 간 불일치는 반영하지 않는다.
- 미래의 SR이 라이브러리와 다른 분야(예: 임상 RCT 위주)라면 사전분포가 맞지 않을 수 있다. UI는 "라이브러리 분야: 영양·동물 전임상 위주"라고 표시한다.

## 8. 검색 API 세부

- **PubMed**: E-utilities esearch(usehistory) + efetch(XML)를 쓴다.
  - 결과가 10,000건을 넘으면 출판연도 구간으로 자동 분할해 각 구간을 10,000건 미만으로 만든다.
  - 속도는 초당 3요청으로 제한한다. 사용자가 무료 NCBI 키를 입력하면 초당 10요청까지 쓴다.
- **Europe PMC**: REST search에 cursorMark를 쓰고 pageSize는 1000, resultType은 core(초록 포함)로 둔다.
- **OpenAlex**: works 검색에 cursor를 쓰고 per-page는 200으로 둔다. 초록은 abstract_inverted_index를 복원해서 얻는다. polite pool을 쓰기 위해 mailto를 설정한다.
- **공통 처리**
  - 지수 백오프로 재시도한다 (최대 5회).
  - 부분 실패는 명시적으로 표시하고, 조용히 누락하지 않는다.
  - 모든 응답은 캐시하고, 실행 manifest에 질의 문자열·시각·건수를 기록한다.
- **사전 확인 항목**: 이 실행 환경에서 각 API에 접근할 수 있는지, 대용량 요청에 제한이 있는지 구현 첫 단계에서 실측한다.

## 9. 전문 처리

- **OA 전문 확보 순서**: Europe PMC fullTextXML(PMCID가 있을 때) → Unpaywall `best_oa_location` PDF(무료, 이메일 필요) → 사용자 업로드
  - PDF는 기존 `upload_safety.extract_pdfs`와 `ma_core.segment_pages`로 처리한다.
- **규칙 탐지기**: outcome 동의어가 나오는 문장과 표 행에서 아래 패턴을 찾는다.
  - 수치: `mean ± SD/SEM`, `x (y)`, `n =`, 표 캡션의 `values are mean ± SD/SEM`
  - 결과는 근거 문장, 페이지, 신뢰 등급으로 반환한다.
  - 그림으로만 제시된 경우는 "figure-only, 디지타이징 필요"로 따로 표시한다. 이 경우 기존 figure_evidence를 연결한다.
- **LLM(선택)**: 기존 `ma_core.validate_assessment`의 "근거 인용 실재 검증"을 그대로 적용한다. 원문에 없는 인용은 '불확실'로 강등한다.

## 10. 로컬 LLM

- Ollama HTTP(`localhost:11434/api/chat`, `format: json`, `temperature: 0`)를 쓴다. 모델 이름은 설정값이다.
- CPU 기본값은 3B급 소형 모델이다. GPU에서는 7–8B급 모델로 이름만 바꾸면 되고, 코드 변경은 없다.
- 미설치·미실행이면 자동으로 비활성되고 UI는 "수동 판정 모드"로 표시한다.
- 재연 검증에는 LLM을 넣지 않는다. 정답 라벨을 사람 판정으로 쓰기 때문이다. 따라서 LLM 제안의 정확도(사람 판정과의 일치율)는 별도로 측정해서 보고한다.

## 11. UI (feasibility_page.py)

단계형 화면으로 구성한다.
1. 입력
2. 검색 실행·N 확인
3. 표본 판정 (표, 단축키 O/X, LLM 제안 표시)
4. 2차 표본
5. 전문 확인
6. 결과

결과 화면에는 outcome별 예측분포 그림, 구간, 판정, 검증 성적 배지("8개 SR 재연에서 80% 구간 포함률 xx%")를 넣는다. 진행 상태는 기존 `projects.save_project_state`로 프로젝트별 저장하므로 중단 후 재개할 수 있다.

## 12. 오류 처리 원칙

- 데이터 손실을 막는다. 판정은 클릭할 때마다 즉시 저장한다.
- 불확실성은 숨기지 않고 넓힌다. 결측, 미확보, 가정이 있으면 구간을 넓히고 그 이유를 표시한다.
- 외부 입력은 신뢰 경계에서 검증한다. 업로드는 기존 upload_safety를 거치고, API 응답은 스키마를 확인한다.

## 13. 테스트

- **estimator**: 정답을 아는 합성 모집단에서 반복 실험해 구간 포함률이 명목값 ±3%p 안에 드는지 확인한다. 극단 사례(포함 0편, 전수 조사, 결측 100%)도 검사한다.
- **search_apis**: 녹화한 응답 fixture로 파싱, 페이지네이션, 연도 분할을 오프라인에서 테스트한다.
- **ETL**: 소형 fixture 워크북으로 라벨 매핑과 단계 연결을 테스트한다.
- **replay**: 라이브러리 전체 검증 보고서를 생성한다. 이것이 합격 게이트다.
- 기존 테스트(test_ma_core, selftest_v36 등)가 회귀하지 않는지 확인한다.
